# Текущее состояние проекта

Дата фиксации: 2026-05-10.

## Главная линия

Проект делится на несколько самостоятельных частей:

- `adaptive-engine` - V1 / Geometry Engine. Отвечает за сетку, координаты, операции, границы, ошибки и базовую геометрию.
- `composition-engine` - V2 / Composition Engine. Отвечает за смысловую композицию блоков, роли, связи, группы, зоны и рекомендации по поведению.
- `navigation-engine` - V3 / Navigation Engine. Отвечает за страницы, вкладки, маршруты и состояние host-навигации.
- `engine-runtime` - мост между V1, V2 и V3. Его задача - принимать решение, можно ли применить кандидат от V2 к геометрии V1.
- `engine-adapter` - слой общения тестового UI с движками.
- `src` - тестовая рабочая зона и debug-интерфейс.
- `safety-system` - проверки структуры, импортов, тестов и сборки.

## Что сейчас важно

V2 не отключается. Тестовая рабочая зона явно запускает адаптер в режиме `AUTO`.

Это означает:

- V1 продолжает держать строгую геометрию и не принимает хаотичные изменения.
- V2 автоматически анализирует композицию при изменении сцены и сетки.
- При изменении рабочей области V2 может предложить безопасную подгонку через runtime-мост.
- Runtime-мост проверяет, можно ли применить кандидат V2 без нарушения законов V1.
- Кнопка `v2 fix` остается ручным проверочным действием, но не является единственным местом работы V2.

## Что не включаем обратно

Старую автоматическую подгонку только силами V1 не считаем основным поведением. Она может быть полезна как `safe`-режим, но сейчас главный путь - `V2 -> runtime bridge -> V1`.

## Текущее состояние V2

V2 уже видит:

- блоки;
- типы блоков;
- группы;
- связи;
- рабочие зоны;
- роли вроде `header`, `sidebar`, `content`, `control`, `warning`;
- сигналы и предложения по композиции;
- критические нарушения, при которых композицию нельзя применять как есть.

V2 еще калибруется:

- поведение на очень узких рабочих областях;
- перенос боковых и правых блоков;
- сохранение дизайнерской композиции при сжатии;
- выбор запасного сценария, когда V1 отклоняет первый кандидат;
- автоматическое применение без визуальных скачков.

## Текущее состояние V3

V3 уже дает базовую навигационную структуру для тестовой зоны:

- страницы;
- вкладки;
- активную рабочую область;
- состояние host-навигации.

Глубокая логика меню и вложенных локальных навигаций остается следующим этапом.

## Красная линия

V1 нельзя ломать ради V2. Если V2 предлагает невозможную геометрию, V1 должен отказать. После отказа система не должна падать: V2 должен предложить другой сценарий или оставить сцену в стабильном состоянии.

## Следующий фокус

1. Убедиться, что `AUTO`-режим V2 явно работает в тестовой рабочей зоне.
2. Убрать битую кодировку из сообщений runtime/adaptor/UI.
3. Проверить, что отчеты V2 обновляются автоматически.
4. Продолжить калибровку V2 на узких экранах.
5. Не фиксировать финальные документы по поведению, пока пользователь не подтвердит тестами, что поведение стабильно.
