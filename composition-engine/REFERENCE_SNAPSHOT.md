# Reference composition snapshot

`reference snapshot` - отдельный слой памяти внутри `composition-engine`.

Он фиксирует авторскую композицию: где дизайнер поставил блоки, какие блоки были рядом, какие зазоры между ними, к каким краям они были привязаны и в какие группы попали.

## Зачем нужен слой

V2 уже умеет смотреть на текущую рабочую область и говорить:

- какие блоки есть;
- какие роли у блоков;
- какие связи и группы обнаружены;
- где есть предупреждения или ошибки.

Но этого мало для аккуратной адаптации. При сжатии экрана нужно понимать не только текущее состояние, но и исходный замысел: порядок, воздух, соседство, привязки и смысловые группы. Эту задачу выполняет `reference snapshot`.

## Что он сохраняет

- `source` - метрики рабочей области на момент снимка.
- `blocks` - блоки с областью, ролью, типом, привязками и позицией в workspace.
- `groups` - группы, которые уже нашел V2.
- `relations` - смысловые связи, которые уже нашел V2.
- `gaps.horizontal` и `gaps.vertical` - ближайшие зазоры между блоками.

## Чего он не делает

- Не двигает блоки.
- Не чинит ошибки.
- Не заменяет диагностику.
- Не спорит с V1.
- Не принимает финальное решение за адаптер.

Это память о композиции, а не исполнитель.

## Граница с будущей адаптацией

Следующий слой может использовать `reference snapshot`, чтобы сравнить:

- как композиция была задумана;
- какая рабочая область доступна сейчас;
- какие блоки можно сжать, перенести, сложить в колонку или оставить у края.

Так V2 не будет противоречить сам себе: диагностика отвечает за состояние, reference snapshot отвечает за замысел, а будущий apply/adapt слой будет отвечать за действие.
