# Engine Runtime

`engine-runtime` - постоянный мост P2 между частями Adaptive Engine.

Runtime не является UI, не является V1, V2 или V3. Его задача - связать решения разных движков и не дать системе применить небезопасную раскладку.

## Цепочка принятия решения

```text
P1 adapter
  -> P2 runtime
    -> V2 composition candidate
      -> V1 geometry check
        -> accepted / rejected
```

## Ответственность

- V1 проверяет физику: сетку, границы, размеры, пересечения.
- V2 читает композицию: роли, группы, связи, смысловые зоны.
- V3 описывает навигацию: страницы, вкладки, маршруты.
- Runtime решает, можно ли передать кандидата дальше.
- Adapter применяет только тот результат, который прошел проверку.

## Важное правило

Если V2 предложил раскладку, а V1 ее отклонил, runtime не должен применять ее силой.

Правильное поведение:

```text
V2 предложил кандидата
V1 отклонил геометрию
runtime вернул отказ
V2 пробует следующий сценарий
adapter не ломает текущую рабочую область
```

Неправильное поведение:

```text
V2 предложил кандидата
V1 сказал "нет"
adapter все равно применил
блоки ушли за границы или наложились друг на друга
```

## Для чего нужен runtime

Runtime нужен не временно. Это постоянный слой безопасности между смыслом и геометрией.

V2 может становиться умнее, но V1 остается законом физики. Runtime удерживает эту границу.

## Что runtime должен возвращать

Минимальный смысл ответа:

- `accepted` - можно ли применять результат;
- `status` - итоговое состояние;
- `reason` - причина отказа или принятия;
- `items` - безопасные элементы для применения;
- `candidateItems` - предложенная V2 версия;
- `composition` - отчет V2;
- `geometry` - отчет V1;
- `handoff` - кому дальше принадлежит управление.
