# V2 как слой композиции

Этот документ фиксирует роль V2 Composition Engine.

V2 не должен быть просто улучшенной подгонкой блоков по сетке. Его задача шире: понимать блоки как смысловые рабочие области, видеть связи между ними и предлагать композиционные решения для разных размеров экрана.

## Разделение ответственности

```text
V1 / Geometry Engine      -> строгая геометрия, сетка, координаты, операции, отказы
Adapter                   -> переводчик между UI, V1, V2 и runtime
V2 / Composition Engine   -> композиция, роли блоков, связи, предложения
V3 / Navigation Engine    -> страницы, вкладки, маршруты, переходы
Host/UI                   -> отображение, ввод пользователя, реальные компоненты сайта
```

V1 остается законом. V2 может анализировать и предлагать решения, но применяемые изменения должны проходить через adapter и проверяемые операции V1.

## Что V2 должен понимать

V2 смотрит на блоки как на множество рабочих областей:

- блок может быть самостоятельной областью;
- блок может содержать текст, кнопки, формы, списки, таблицы и другие элементы;
- блок может иметь внутреннюю раскладку;
- блок может менять внутреннее поведение при изменении размера;
- блок может быть связан с другими блоками;
- группа блоков может перестраиваться как единая композиция.

Пример будущего поведения:

```text
desktop -> блоки стоят рядом и сохраняют дизайнерскую композицию
tablet  -> блоки сближаются, ужимаются или меняют приоритет
mobile  -> блоки могут переходить в колонку, уплотняться и менять внутреннюю подачу
```

## Внутреннее содержимое блока

Для V2 блок не заканчивается на `x/y/w/h`.

У блока может быть внутренний контракт:

- тип содержимого;
- минимальные размеры для содержимого;
- допустимые режимы отображения;
- правила переноса;
- правила изменения шрифта;
- связи с данными;
- зависимости от других блоков.

Это направление, а не текущий обязательный API.

## Как V2 общается с V1

Правильная схема:

```text
V2 анализирует композицию
V2 формирует предложение или применяемый кандидат
Adapter переводит это в команды или операции
V1 проверяет
V1 возвращает ok/rejection/report
Adapter показывает результат host/UI
```

Если V1 говорит “нельзя”, V2 не должен обходить запрет. Нужно предложить другой сценарий, действуя по известным законам.

## Граница включения

Граница передачи зафиксирована в `engine-adapter/contracts/adapterBehaviorModes.js`.

```text
off     -> ничего не применять автоматически
safe    -> работает старая V1-защита
suggest -> V2 может предложить решение
auto    -> V2 может вернуть применяемое решение
```

Рабочий режим по умолчанию: `off`. Ручная команда `v2 fix` является отдельным действием adapter/runtime и не должна маскироваться под автоматическую адаптацию.

## Стоп-линия

V2 не внедряется внутрь V1.

V1, adapter, runtime и safety-system должны оставаться проверяемыми слоями. V2 развивается отдельно, пока его предложения не станут достаточно стабильными для автоматического режима.
