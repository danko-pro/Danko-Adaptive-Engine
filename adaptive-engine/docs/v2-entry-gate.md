# V2 Entry Gate

Этот документ фиксирует правило: V2 не возвращается внутрь V1 скрытым изменением.

## Текущее решение

V1 остается стабильным layout kernel.

V2, если он понадобится, должен проектироваться как отдельный слой со своим фасадом. Он не должен незаметно встраиваться в `adaptive-engine/core/index.js`, `engine-adapter/index.js` или рабочий тестовый UI.

## Где может жить V2

Допустимые варианты для будущего обсуждения:

- отдельный корневой слой рядом с `adaptive-engine`;
- отдельный слой рядом с `src`, если это экспериментальный UI/UX runtime;
- отдельный фасад, например `adaptive-engine-v2/index.js` или другой явно названный вход;
- отдельные тесты и safety-checks, не смешанные с V1.

## Что запрещено для V1

- Возвращать `adaptive-engine/behavior` без отдельного решения.
- Экспортировать V2 behavior из `adaptive-engine/core/index.js`.
- Экспортировать V2 behavior из `engine-adapter/index.js`.
- Подключать автоматическое поведение блоков в рабочий UI по умолчанию.
- Молча менять настоящий layout при изменении workspace.

## Условия для возвращения V2

Перед разработкой V2 нужно отдельно определить:

- зачем V2 нужен;
- какие сценарии он решает;
- какие сценарии он не имеет права трогать;
- какой у него публичный фасад;
- какие режимы доступны: `strict`, `suggest`, `auto`;
- какой режим включен по умолчанию;
- как V2 откатывается при ошибке;
- как V2 объясняет отказ;
- как V2 проверяется в safety-system.

## Правило по умолчанию

```text
V1 работает строго.
V2 не активен.
Любое умное поведение должно быть явным режимом.
```

## Текущая страховка V1

В V1 допускается только защитная проекция adapter:

- блок не исчезает при ресайзе;
- блок у правого края остается у правого края;
- блок на всю ширину остается на всю ширину;
- источник правды не перезаписывается временной проекцией.

Эта страховка не считается V2 behavior, потому что она не перестраивает layout, не двигает соседние блоки и не принимает решений вместо пользователя.
