# Engine Adapter

`engine-adapter` — отдельный корневой слой между UI и `adaptive-engine`.

## Назначение

Adapter переводит действия интерфейса в язык движка:

- pointer/click -> grid cell;
- cell -> selection;
- click or rectangle selection + Enter + text -> create-area intent;
- drag -> move-area operation;
- resize handle -> set-area operation;
- engine result -> данные для UI;
- rejection -> rollback UI.

## Правило слоя

```text
src -> engine-adapter -> adaptive-engine/core/index.js
```

`engine-adapter` не рисует интерфейс и не зависит от React.

`adaptive-engine` не знает про adapter.

## Структура

```text
engine-adapter/
├── commands/
├── contracts/
├── feedback/
├── input/
├── interaction/
├── layout-map/
├── selection/
└── index.js
```

## Текущие возможности

- выбор ячейки или area;
- создание area из ячейки и текста;
- создание area из выделенной прямоугольной области и текста;
- применение operation;
- движение area через pointer;
- изменение размера area через handles;
- форматирование названий, target и ошибок;
- rollback UI при отказе движка;
- создание диагностической карты позиционирования layout-map.

## Следующий фокус

Новые UX-сценарии должны появляться здесь, если они являются переносимой логикой:

- выделение прямоугольной области;
- preview операции до применения;
- delete/rename/copy на уровне adapter-команд;
- перевод rejection в человеческие сообщения;
- простая история действий.

## Почему это отдельно от src

`src` сейчас является тестовым UI. Adapter должен быть переносимым слоем, который позже можно
использовать в другом host-проекте, например в калькуляторе отделки.

## Защитная проекция при ресайзе

Adapter содержит минимальную страховку для отображения блоков при изменении размеров сетки.

Это не автоматическое поведение V2. Adapter не перестраивает layout самовольно и не двигает соседние блоки как полноценный responsive engine.

Правило V1:

```text
источник правды -> временная проекция под текущую сетку -> UI
```

Источник правды не должен перезаписываться временной проекцией. Это защищает блоки от исчезновения при быстром изменении окна.

Поддержанные защитные случаи:

- блок на всю ширину остается на всю ширину при сжатии и расширении;
- блок у правого края остается у правого края;
- блок в середине не меняет позицию без явной операции;
- если блок стал шире текущей сетки, он временно ужимается только для отображения.

Проверка:

```bash
npm run test:adapter-fit
```
