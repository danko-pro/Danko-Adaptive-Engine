# Adaptive Engine System

Этот документ фиксирует общую терминологию проекта после разделения движка на основные и вспомогательные части.

## Основные части

```text
V1 / Geometry Engine      -> adaptive-engine/
V2 / Composition Engine   -> composition-engine/
V3 / Navigation Engine    -> navigation-engine/
```

Все три части являются частями одного большого Adaptive Engine, но каждая отвечает за свой уровень.

## Вспомогательные части

```text
P1 / Engine Adapter   -> engine-adapter/
P2 / Engine Runtime   -> engine-runtime/
P3 / Safety System    -> safety-system/
P4 / Debug Lab        -> src/debug/
```

Вспомогательные части не должны подменять основные движки. Их задача - связывать, проверять, показывать и защищать.

## Граница ответственности

V1 отвечает за физику сетки:

- координаты;
- размеры;
- границы;
- коллизии;
- строгий отказ.

V2 отвечает за композицию:

- роли блоков;
- группы;
- связи;
- зоны рабочей области;
- рекомендации и будущие команды перестройки.

V3 отвечает за навигацию:

- страницы;
- вкладки;
- меню;
- зарезервированные навигационные зоны.

P2 runtime отвечает за мост:

```text
V2 plan -> V1 geometry check -> apply / reject / needs composition command
```

## Почему runtime нужен постоянно

На узких экранах V1 может честно отклонить старую геометрию, потому что блоки выходят за сетку или сталкиваются. Это не ошибка V1.

Но если V2 только сообщает о проблеме и не возвращает применяемую команду, возникает замкнутый круг:

```text
V1 отклонил -> V2 увидел -> применить нечего
```

Поэтому runtime должен явно различать:

- текущую раскладку можно применять;
- композиция критически сломана;
- геометрия не проходит, и V2 должен вернуть composition-command.

## Текущее правило

Сейчас V2 остается наблюдающим и диагностическим слоем. Runtime уже фиксирует мост, но не перестраивает layout сам.

Следующий этап V2 - научиться возвращать применяемую команду перестройки, которую V1 сможет снова проверить.
