# Composition Policy

`composition policy` - это слой дизайнерских правил для V2.

Он не заменяет строгие правила геометрии и не двигает блоки сам. Его задача - описать, какой ритм и какие предпочтения должен уважать `composition-engine`.

## Жесткие правила и дизайнерские правила

Жесткие правила:

- блоки не должны пересекаться;
- блоки не должны выходить за рабочую область;
- обязательные роли не должны теряться.

Дизайнерские правила:

- между блоками нужен минимальный зазор;
- некоторые блоки должны сохранять визуальную роль;
- некоторые группы лучше переносить вместе;
- на узких экранах композиция может требовать другого порядка.

Жесткое нарушение дает `error`.

Дизайнерское нарушение дает `warning` и proposal.

## Текущая политика

```js
policy: {
  spacing: {
    minGap: 1,
    preferredGap: 1
  }
}
```

`minGap` - минимальный допустимый зазор между соседними блоками, если они стоят в одной строке или колонке.

`preferredGap` - желаемый зазор. Сейчас он зафиксирован в контракте, но пока не используется как отдельная мягкая рекомендация.

## Что уже умеет V2

Если `minGap` задан и два блока стоят вплотную, V2 возвращает:

- issue `BLOCK_GAP_TOO_SMALL`;
- proposal `increase-block-gap`;
- статус `warning`, а не `error`.

Это значит: композиция рабочая, но дизайнерский ритм нарушен.

## Что будет дальше

Следующий шаг - научить V2 строить recovery-предложения:

- куда сдвинуть блок;
- какую группу сложить вертикально;
- какой блок сохранить у края;
- какой блок сделать главным в потоке.

Adapter сможет показывать эти предложения, а применять их будет только через V1-операции.
