# Composition Engine

`composition-engine` - слой V2 внутри Adaptive Engine.

V2 не заменяет V1 и не должен напрямую обходить геометрию. Его задача - понимать композицию: роли блоков, группы, связи, смысловое расположение и ожидаемое поведение при изменении размера рабочей области.

## Место в системе

```text
V1 / Geometry Engine     -> сетка, координаты, границы, коллизии
V2 / Composition Engine  -> смысл, роли, группы, связи, сценарии адаптации
V3 / Navigation Engine   -> страницы, вкладки, переходы, навигационный контекст
P2 / Engine Runtime      -> мост между V1, V2 и V3
P1 / Engine Adapter      -> связь движков с тестовым UI или host-проектом
```

V2 может предложить новую раскладку, но итоговая геометрия всегда должна пройти проверку V1.

## Что V2 уже должен понимать

- какие блоки есть в рабочей области;
- какие роли у блоков: `header`, `content`, `sidebar`, `control`, `warning`, `unknown`;
- какие блоки касаются краев рабочей области;
- какие блоки занимают всю ширину или высоту;
- какие блоки связаны друг с другом;
- какие блоки образуют смысловую группу;
- где находится блок: верх, низ, левый край, правый край, центр;
- какой профиль рабочей области сейчас активен: desktop/tablet/compact/mobile;
- какие композиционные риски есть в текущем состоянии.

## Главный закон V2

V2 не должен адаптировать раскладку от последней адаптированной версии.

Источником правды должна быть reference map: снимок авторской композиции, которую дизайнер или пользователь собрал в широком/исходном состоянии.

```text
reference map -> V2 candidate -> V1 geometry check -> adapter apply
```

Если V2 начинает пересчитывать от уже сжатой версии, блоки постепенно теряют исходный смысл: сжимаются сильнее, не восстанавливаются при расширении и могут начать вести себя хаотично.

## Что V2 не должен делать

- не импортировать UI;
- не импортироваться внутрь `adaptive-engine/core/index.js`;
- не обходить V1;
- не применять изменения сам;
- не перезаписывать reference map адаптированной раскладкой;
- не считать любые свободные координаты одинаково правильными;
- не игнорировать роль блока и связи с другими блоками.

## Режимы

```text
off     -> V2 отключен
suggest -> V2 анализирует и возвращает рекомендации
auto    -> V2 строит кандидата, runtime проверяет его через V1
```

Даже в `auto` V2 не получает абсолютную власть. Если V1 отклоняет кандидата, runtime должен вернуть отказ, а V2 должен предложить другой сценарий.

## Ключевые документы

- `BEHAVIOR_PROFILES.md` - профили поведения блоков и правила адаптации.
- `REFERENCE_SNAPSHOT.md` - зачем нужен исходный снимок композиции.
- `POLICY.md` - политика V2 и границы ответственности.
