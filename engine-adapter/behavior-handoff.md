# Передача поведения между V1 и V2

`engine-adapter` является границей, где UI, V1 Geometry Engine и V2 Composition Engine договариваются, кто сейчас имеет право менять координаты блоков.

## Зачем здесь режимы

Adapter видит:

- действия UI;
- текущие `items`;
- `metrics`;
- результат операций V1;
- состояние выбора;
- текущий режим поведения.

Поэтому именно adapter решает, оставить блоки как есть, применить старую защитную V1-проекцию или передать сцену в V2.

## Контракт режимов

```text
behaviorMode = off     -> ничего не применять автоматически
behaviorMode = safe    -> включить старую защитную V1-проекцию
behaviorMode = suggest -> V2 получает данные и возвращает отчет
behaviorMode = auto    -> V2 получает данные и в будущем сможет вернуть применяемое решение
```

Тестовый UI по умолчанию работает в режиме `off`. Это важно: если блоки двигаются сами, значит включен отдельный режим или команда, а не скрытая автоматика.

## Важное ограничение

Нельзя одновременно применять V1-проекцию и V2-поведение. Иначе они начнут спорить за координаты блоков.

Функции границы:

- `shouldUseAdapterSafetyProjection`;
- `shouldPassBehaviorToV2`;
- `resolveAdapterBehaviorMode`.

Они экспортируются из `engine-adapter/index.js`.
